Архитектурные принципы (обязательные)
Clean Architecture

Строго соблюдать разделение:

domain
use cases
repository abstraction
data
presentation

Domain не зависит ни от одной платформы.

Component-based Architecture

Каждая фича представляет собой отдельный компонент.

Компонент содержит:

состояние;
бизнес-логику;
обработку событий;
взаимодействие с Use Cases;
навигацию через Decompose.

Компоненты максимально независимы.

Decompose

Использовать только компонентную навигацию.

Навигация не должна находиться внутри Compose UI.

State хранится в Component.

Compose отображает только состояние.

Навигация осуществляется исключительно через компоненты.

Shared UI

Приоритет — максимально общий UI.

Если компонент можно реализовать в Shared UI — он должен быть реализован именно там.

Платформенные реализации использовать только при объективной необходимости.

Не переносить UI в platform-модули без веской причины.

Platform-specific код

Platform-specific код допустим только если невозможно реализовать решение в Shared.

Примеры:

Permissions
Camera
File Picker
Native API
Push Notifications
Platform Storage
Platform Intents
Browser API

Во всех остальных случаях использовать Shared.

State Management

Использовать:

immutable state
StateFlow
UI State
Event
Action
Intent (если используется)

Не хранить бизнес-логику внутри Compose.

Следовать принципам:

Stateless UI
State Hoisting
