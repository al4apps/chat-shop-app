# chat-list Specification

## Purpose
Описывает стартовый экран со списком диалогов: источник данных, порядок элементов, отображение статусов и переходы к диалогу или созданию нового заказа.

## Requirements

### Requirement: Источник данных
Список диалогов SHALL строиться исключительно из локальной БД и SHALL обновляться реактивно при изменении данных синхронизацией.

#### Scenario: Обновление из БД
- **WHEN** синхронизация сохраняет новый или изменённый диалог
- **THEN** список обновляется без отдельного запроса из UI
- **AND** данные берутся из `Flow` БД

### Requirement: Сортировка
Система SHALL сортировать диалоги по времени последнего сообщения (`lastMessageAt`), а при его отсутствии — по времени создания (`createdAt`), по убыванию.

#### Scenario: Диалоги с сообщениями
- **WHEN** у диалогов есть `lastMessageAt`
- **THEN** первым показывается диалог с самым поздним временем
- **AND** диалоги без `lastMessageAt` сортируются по `createdAt`

### Requirement: Содержимое элемента
Элемент списка SHALL показывать описание заказа или «Заказ №N», статус заказа либо статус диалога и метку времени последней активности.

#### Scenario: Заказ с описанием
- **WHEN** у диалога заполнен `orderDescription`
- **THEN** заголовком элемента является описание заказа

#### Scenario: Заказ без описания
- **WHEN** описания заказа нет
- **THEN** заголовком является «Заказ №N»

#### Scenario: Статус в подзаголовке
- **WHEN** у диалога есть статус заказа
- **THEN** подзаголовком показывается статус заказа
- **AND** при его отсутствии — статус диалога

### Requirement: Порядковый номер
Система SHALL определять номер заказа `N` по порядку создания диалогов, чтобы номер оставался стабильным при сортировке по активности.

#### Scenario: Сортировка изменилась
- **WHEN** новый диалог становится первым по последней активности
- **THEN** номера уже существующих заказов не меняются

### Requirement: Пустой список
Система SHALL показывать пустое состояние списка и кнопку создания заказа, если в БД нет диалогов.

#### Scenario: Нет диалогов
- **WHEN** список диалогов пуст
- **THEN** показывается пустое состояние
- **AND** доступна кнопка создания заказа

### Requirement: Открытие диалога
Система SHALL открывать выбранный диалог по нажатию на элемент списка.

#### Scenario: Нажатие на диалог
- **WHEN** пользователь нажимает на элемент списка
- **THEN** открывается экран этого диалога

### Requirement: Создание заказа
Система SHALL по кнопке «+» открывать экран нового заказа, не создавая диалог до первой отправки сообщения.

#### Scenario: Нажатие «+»
- **WHEN** пользователь нажимает «+»
- **THEN** открывается экран нового заказа
- **AND** запрос `POST /dialogs` не выполняется до отправки сообщения
