# sync-and-files Specification

## Purpose
Описывает приём данных с сервера: инкрементальный поллинг диалогов и сообщений, работу с курсором `seq`, поведение в фоне и кэширование входящих файлов по presigned-ссылкам.

## Requirements

### Requirement: БД как источник истины
Система SHALL сохранять данные сервера в SQLDelight и SHALL отдавать UI только `Flow` из БД; сетевые ответы SHALL не отображаться напрямую.

#### Scenario: Данные пришли с сервера
- **WHEN** синхронизация получила новые диалоги или сообщения
- **THEN** они сохраняются в БД в транзакции
- **AND** UI обновляется из `Flow` БД

### Requirement: Поллинг списка диалогов
Система SHALL опрашивать список диалогов каждые 12 секунд при авторизованной сессии и переднем плане, а при возврате в foreground SHALL выполнять немедленный запрос.

#### Scenario: Приложение на переднем плане
- **WHEN** сессия `Authorized` и приложение активно
- **THEN** список диалогов обновляется раз в 12 секунд

#### Scenario: Возврат из фона
- **WHEN** приложение возвращается на передний план
- **THEN** синхронизация выполняется немедленно
- **AND** периодический опрос возобновляется

### Requirement: Поллинг открытого диалога
Система SHALL опрашивать ленту открытого диалога каждые 4 секунды по курсору `afterSeq` и SHALL останавливать опрос при закрытии экрана или уходе в фон.

#### Scenario: Диалог открыт
- **WHEN** экран диалога активен
- **THEN** его лента опрашивается раз в 4 секунды после `lastSyncedSeq`

#### Scenario: Диалог закрыт
- **WHEN** пользователь уходит с экрана диалога
- **THEN** частый опрос этой ленты прекращается

### Requirement: Инкрементальная загрузка
Система SHALL запрашивать сообщения после `lastSyncedSeq`, сохранять `nextAfterSeq` и SHALL продолжать страницы, пока размер страницы равен лимиту; курсор SHALL двигаться только вперёд.

#### Scenario: Несколько страниц
- **WHEN** сервер вернул полную страницу сообщений
- **THEN** система запрашивает следующую страницу
- **AND** продолжает, пока страница не окажется неполной

#### Scenario: Курсор не откатывается
- **WHEN** приходит сообщение с меньшим `seq`
- **THEN** сохранённый `lastSyncedSeq` не уменьшается

### Requirement: Фоновый режим
Система SHALL прекращать периодический опрос в фоне и без авторизации; пропущенные обновления SHALL догружаться при следующем foreground-запуске.

#### Scenario: Уход в фон
- **WHEN** приложение уходит в фон
- **THEN** циклы поллинга останавливаются

#### Scenario: Нет авторизации
- **WHEN** сессия не `Authorized`
- **THEN** сетевые циклы синхронизации не выполняются

### Requirement: Разовая синхронизация
Система SHALL поддерживать разовую синхронизацию списка для Bootstrap и разовую догрузку ленты диалога по курсору.

#### Scenario: Bootstrap
- **WHEN** Home запускает Bootstrap
- **THEN** выполняется один запрос списка диалогов до выбора стартового экрана

#### Scenario: Открытие диалога
- **WHEN** открывается диалог
- **THEN** лента догружается с сохранённого курсора

### Requirement: Скачивание файлов
Система SHALL скачивать входящие файлы по presigned URL отдельным HTTP-клиентом без `Authorization`, кэшировать байты по `file.id` и SHALL пропускать уже скачанные файлы.

#### Scenario: Новый входящий файл
- **WHEN** в БД появляется активный файл без локальной копии и с `remoteUrl`
- **THEN** файл скачивается без заголовка `Authorization`
- **AND** байты сохраняются по `file.id`
- **AND** локальный путь записывается в БД

#### Scenario: Файл уже в кэше
- **WHEN** локальная копия файла уже существует
- **THEN** повторное скачивание не выполняется

### Requirement: Временность URL
Система SHALL не считать `file.url` постоянной ссылкой и SHALL повторять скачивание после обновления `remoteUrl` при следующем опросе.

#### Scenario: Ссылка протухла
- **WHEN** скачивание по `remoteUrl` завершилось ошибкой
- **THEN** система не удаляет сообщение
- **AND** повторяет попытку после получения свежего `remoteUrl`
- **AND** показывает состояние загрузки в UI

### Requirement: Устойчивость к ошибкам
Система SHALL не прерывать циклы синхронизации при сетевой ошибке и SHALL повторять запрос на следующем тике, сохраняя доступность данных из БД.

#### Scenario: Ошибка сети при поллинге
- **WHEN** очередной запрос завершился сетевой ошибкой
- **THEN** цикл продолжает работу
- **AND** UI продолжает показывать данные из БД
