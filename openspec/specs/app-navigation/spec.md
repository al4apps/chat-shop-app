# app-navigation Specification

## Purpose
Описывает стартовый роутинг приложения, стек экранов после авторизации, переходы между списком чатов и диалогом, а также реакцию на потерю сессии.

## Requirements

### Requirement: Стартовый экран
Система SHALL выбирать стартовый экран при запуске: `Home` при действующей сессии, `Auth` при отсутствии сессии и установленном флаге онбординга, иначе `Onboarding`.

#### Scenario: Есть сессия
- **WHEN** приложение запускается с сохранёнными токенами
- **THEN** открывается Home

#### Scenario: Нет сессии и онбординг пройден
- **WHEN** токенов нет, а флаг онбординга установлен
- **THEN** открывается экран авторизации

#### Scenario: Нет сессии и онбординг не пройден
- **WHEN** токенов нет и флаг онбординга не установлен
- **THEN** открывается онбординг

### Requirement: Завершение авторизации
Система SHALL после успешной авторизации заменять стек на `Home`, исключая возврат на экраны авторизации кнопкой «Назад».

#### Scenario: Успешный вход
- **WHEN** пользователь завершил ввод кода
- **THEN** открывается Home
- **AND** назад на экран кода или телефона невозможен

### Requirement: Bootstrap Home
Home SHALL при старте выполнить разовую синхронизацию списка диалогов и заменить `Bootstrap` на `FirstOrder`, если диалогов нет, или на `ChatList`, если диалоги есть.

#### Scenario: Диалогов нет
- **WHEN** после синхронизации в БД нет диалогов
- **THEN** открывается экран первого заказа

#### Scenario: Диалоги есть
- **WHEN** после синхронизации в БД есть хотя бы один диалог
- **THEN** открывается список чатов

### Requirement: Переход из списка в диалог
Система SHALL открывать `Dialog(id)` поверх `ChatList` по нажатию на диалог и SHALL возвращаться в список по «Назад».

#### Scenario: Открытие диалога
- **WHEN** пользователь нажимает на элемент списка
- **THEN** открывается диалог с выбранным id

#### Scenario: Возврат из диалога
- **WHEN** пользователь нажимает «Назад» в диалоге
- **THEN** открывается список чатов

### Requirement: Новый заказ из списка
Система SHALL открывать `NewOrder` поверх `ChatList` по кнопке «+»; диалог SHALL создаваться только при первой отправке, а возврат без отправки SHALL не создавать диалог.

#### Scenario: Открытие нового заказа
- **WHEN** пользователь нажимает «+» в списке
- **THEN** открывается экран нового заказа

#### Scenario: Возврат без отправки
- **WHEN** пользователь открывает новый заказ и возвращается назад, ничего не отправив
- **THEN** новый диалог не создаётся
- **AND** список остаётся прежним

#### Scenario: Первая отправка
- **WHEN** пользователь отправляет первое сообщение на экране нового заказа
- **THEN** создаётся диалог
- **AND** экран нового заказа заменяется диалогом

### Requirement: Первый заказ
Система SHALL после первой отправки на экране `FirstOrder` заменять стек на `ChatList` и `Dialog(id)`, чтобы «Назад» вёл в список.

#### Scenario: Первый заказ отправлен
- **WHEN** пользователь отправляет первое сообщение на стартовом экране первого заказа
- **THEN** создаётся диалог
- **AND** стек становится `ChatList` → `Dialog(id)`

### Requirement: Потеря сессии
Система SHALL при переходе сессии в `Unauthorized` заменять текущий стек Home на `Auth`.

#### Scenario: Refresh невозможен в Home
- **WHEN** сессия становится `Unauthorized`, пока открыт любой экран Home
- **THEN** открывается экран авторизации
- **AND** экраны Home удаляются из стека

### Requirement: Системная кнопка «Назад»
Система SHALL обрабатывать «Назад» через Decompose: полноэкранный просмотр изображения закрывается первым, затем активный экран; дубли экранов в стеке SHALL не создаваться.

#### Scenario: Назад при открытом изображении
- **WHEN** пользователь нажимает «Назад», когда изображение открыто на весь экран
- **THEN** закрывается только полноэкранный просмотр
- **AND** диалог остаётся открытым

#### Scenario: Открытие уже открытого диалога
- **WHEN** пользователь повторно открывает тот же диалог
- **THEN** дубль экрана в стеке не создаётся
