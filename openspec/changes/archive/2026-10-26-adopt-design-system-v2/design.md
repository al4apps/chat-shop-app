# Design

## Context

См. `proposal.md` — Why. Текущая тема живёт в `core/design/theme`: `AppColors` с системной палитрой, `AppTypography` без собственного `FontFamily` и `AppShapes` с радиусами 8/12/16. Базовые виджеты уже используют эти токены, поэтому замена темы затронет все экраны без изменения их структуры. Шрифтовых ресурсов в `composeResources` сейчас нет.

## Goals / Non-Goals

**Goals:**

- Заменить токены на палитру и типографику принятой дизайн-системы v2.
- Подключить Manrope локально, без сетевой загрузки и без новой библиотеки.
- Сохранить текущую архитектуру виджетов и экранов.
- Добавить `AppBadge` как основу для статусов заказа и диалога.
- Проверить сборку и визуальную целостность на Android и iOS.

**Non-Goals:**

- Не менять навигацию, сеть, БД, API и бизнес-логику.
- Не переверстывать экраны и не добавлять новые продуктовые сценарии.
- Не переносить `ProductCard` из Pencil в код: карточка товара появится в отдельной фиче.
- Не менять существующие радиусы кнопок и пузырей; новые радиусы добавляются отдельными токенами.
- Не делать тёмную тему.

## Decisions

### 1. Manrope статическими файлами, а не variable font

Использовать четыре статических TTF: Regular 400, Medium 500, SemiBold 600, Bold 700. Они кладутся в `shared/src/commonMain/composeResources/font/`.

Почему:

- предсказуемое соответствие весов в Compose Multiplatform на Android и iOS;
- не зависим от поддержки variable fonts в конкретной версии Compose Resources;
- проще проверить метрики и переносы строк.

Альтернативы:

- variable font — меньше файлов, но выше риск разного рендера и маппинга весов;
- системный шрифт — не соответствует принятому макету;
- Google Fonts Provider — лишняя платформенная зависимость и сетевой запрос.

Лицензия Manrope — OFL. Файл лицензии добавляется рядом с ресурсами шрифта или в `docs/licenses/`, чтобы он попадал в поставку.

### 2. `AppTypography` принимает `FontFamily`

`AppTypography` получает параметр `fontFamily` и строит все `TextStyle` с ним. `AppTheme` создаёт `ManropeFamily` из `Res.font.*` и передаёт в `AppTypography`. Значение по умолчанию — `FontFamily.Default`, чтобы previews и тесты не падали без ресурсов.

Почему не глобальная переменная: явная зависимость, проще тестировать и переиспользовать; `CompositionLocal` уже передаёт готовую типографику вниз.

Шкала:

| Токен | Размер / line-height | Вес |
|---|---|---|
| display | 52 / 56 | Bold 700 |
| h1 | 32 / 38 | Bold 700 |
| h2 | 24 / 30 | Bold 700 |
| title | 17 / 22 | SemiBold 600 |
| body | 16 / 24 | Regular 400 |
| caption | 13 / 18 | Regular 400 |
| button | 16 / 20 | SemiBold 600 |

`display` добавляется для крупных акцентов, но не обязан использоваться на существующих экранах.

### 3. Сохранить имена цветовых токенов, добавить `accentSoft`

`AppColors` сохраняет текущие имена (`background`, `surface`, `accent`, `accentPressed`, `textPrimary`, `textSecondary`, `divider`, `disabledContainer`, `disabledContent`, `error`), чтобы не переписывать все вызовы. Добавляется `accentSoft = #E8F1FF`.

Значения v2:

- background `#FFFFFF`
- surface `#F4F7FB`
- accent `#0B63F6`
- accentPressed `#084CC4`
- onAccent `#FFFFFF`
- textPrimary `#101828`
- textSecondary `#5B6472`
- divider `#E3E9F2`
- disabledContainer `#EEF2F7`
- disabledContent `#98A2B3`
- error `#E5484D`
- onError `#FFFFFF`

В `AppTheme` мягкий тинт маппится в `secondaryContainer` / `onSecondaryContainer` Material 3, чтобы стандартные компоненты не теряли семантику.

### 4. Новые радиусы отдельными токенами

`AppShapes` сохраняет `small = 8`, `medium = 12`, `large = 16` и добавляет `extraLarge = 20`, `extraExtraLarge = 24` для карточек и крупных поверхностей. Менять `large` нельзя: он используется пузырями сообщений и может визуально сломать диалог.

### 5. `AppIconButton`: визуальные 40, touch target не меньше 48

В макете действие TopBar занимает 40×40. В Compose сохраняем доступный touch target не меньше 48 dp, а визуальный контейнер/иконку приводим к 40/24. Это осознанное отклонение от пиксельного макета ради доступности.

### 6. `AppBadge` — новый самостоятельный виджет

`AppBadge` — компактный status-chip: фон `accentSoft`, текст `accent`, радиус 999, padding 6/10, Manrope SemiBold 12/16. Виджет принимает текст и не растягивается по ширине. В этом change он только добавляется в дизайн-систему; использование в списке и карточках заказа появится на этапе 11.

### 7. `MessageInputBar` — только токены, без смены структуры

В этом change панель ввода получает новые цвета, типографику и отступы, но сохраняет текущую структуру «скрепка + поле + действие». Полный capsule-редизайн ввода относится к экранной фиче диалога, а не к переносу токенов.

## Risks / Trade-offs

- **Метрики Manrope отличаются от системного шрифта** → проверить все экраны на переносы, обрезку и высоту кнопок; при переполнении уменьшить размер конкретного стиля, а не ломать сетку.
- **iOS может не найти шрифтовой ресурс** → проверить `linkDebugFrameworkIosSimulatorArm64` и запуск на симуляторе; шрифты должны попадать в общий framework.
- **Размер приложения вырастет на несколько TTF** → четыре статических веса; при необходимости заменить на variable font отдельным решением.
- **Смена `h1`/`h2` влияет на онбординг и авторизацию** → визуально проверить эти экраны; при необходимости использовать `display` только там, где он уместен.
- **`AppIconButton` 40×40 может ухудшить доступность** → сохранить touch target 48 и проверить на устройстве.
- **Новые цвета могут снизить контраст на поверхностях** → проверить textPrimary/textSecondary на white и accentSoft; не использовать disabled-цвет для основного текста.
- **OFL-лицензия забыта в поставке** → добавить файл лицензии в ресурсы/документацию и проверить перед релизом.

## Migration Plan

1. Добавить TTF и лицензию.
2. Обновить `AppColors`, `AppTypography`, `AppShapes`, `AppTheme`.
3. Обновить базовые виджеты и добавить `AppBadge`.
4. Собрать Android и iOS, прогнать smoke-тесты.
5. Визуально проверить Onboarding, Auth, ChatList, FirstOrder, Dialog на обеих платформах.
6. При проблемах откатить change целиком: изменения не затрагивают БД, API и навигацию, поэтому миграция данных не нужна.
