## [IOS-VOICE-1] iOS: запись голосовых сообщений

- **Статус:** backlog
- **Приоритет:** высокий (функциональный паритет Android/iOS)
- **Контекст:** `IosAudioRecorder` — заглушка (`isAvailable = false`), на Android запись
  работает через `AndroidAudioRecorder` (MediaRecorder). Воспроизведение на iOS
  реализовано (`AVAudioPlayer`).
- **Факт:** исторически аудио делалось через `expect/actual` без библиотек. Сейчас
  приоритет — сначала стабильная KMP-библиотека.
- **Что проверить:** `KRecorder`, `kmp-record`, `kmp-audio-recorder-player`, `Klarinet`
  и другие актуальные KMP-решения. Критерии: стабильный релиз, поддержка текущих
  Kotlin/Compose Multiplatform, iOS Simulator, AAC/M4A, разрешения, лицензия, размер,
  активность поддержки.
- **Acceptance criteria:**
  - запись, стоп и отмена работают на iOS и Android;
  - запрос разрешения на микрофон и корректная деградация при отказе;
  - длительность 1–120 секунд, реальный `durationSec` уходит в `VOICE`;
  - запись отправляется через outbox и воспроизводится на обеих платформах;
  - есть тест/ручной чек-лист и обновлённый `DEBT.md`.
- **Следующий шаг:** spike-сравнение библиотек, решение в `design.md` change-а.

## [CHAT-IME-1] Android: клавиатура и IME-отступы

- **Статус:** требует воспроизведения
- **Приоритет:** высокий (ломает ввод)
- **Контекст:** `MainActivity` использует `enableEdgeToEdge()`; `HomeContent` —
  `Scaffold` + `modifier.padding(it)`; `DialogScreen` — `imePadding()` на всём Column;
  `FirstOrderScreen` — без `imePadding`; Auth-экраны — `safeContentPadding().imePadding()`.
- **Гипотеза:** двойной учёт IME/insets или конфликт `Scaffold` padding и `imePadding`.
  Это общий UI-риск, не обязательно только тестовый режим.
- **Что проверить:** Android API/устройство, gesture/navigation bar, Dialog и FirstOrder,
  открытие/закрытие клавиатуры, поворот, возврат из фона. Разделить test-mode и general.
- **Acceptance criteria:**
  - при открытой клавиатуре нет ложного верхнего отступа;
  - поле ввода видно, лента скроллится, TopBar не уезжает;
  - «Назад» закрывает клавиатуру, затем экран;
  - поведение одинаково в Dialog и FirstOrder, на Android и iOS.
- **Следующий шаг:** воспроизведение с видео/логами и отдельный change.

## [CHAT-OUTBOX-1] Аудит маршрутизации и отправки сообщений

- **Статус:** требует проверки после `CHAT-TESTSEQ-1`
- **Приоритет:** высокий
- **Контекст:** отправка идёт через `OutboxService` (PENDING → SENDING → SYNCED/FAILED),
  ответ сервера заменяет локальную строку по `localId`/`clientMessageId`.
- **Что проверить:** `dialogId`, `senderRole`, `clientMessageId` на всём пути;
  порядок сообщений в рамках диалога; поведение при ошибке одного диалога; отсутствие
  блокировки других диалогов; корректность `SYNCED`/дублей после ретрая.
- **Acceptance criteria:**
  - сообщение никогда не появляется в чужом диалоге;
  - сторона отправителя совпадает с `senderRole`;
  - FAILED можно повторить с тем же `clientMessageId`;
  - ошибка одного диалога не блокирует остальные;
  - есть интеграционный тест на два диалога и ретрай.
- **Следующий шаг:** проверить после исправления `CHAT-TESTSEQ-1`, затем change при необходимости.
