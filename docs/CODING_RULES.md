# Coding Rules & Principles (From Team Lead)

## Process & Workflow
- Work **поэтапно**: один цикл = одна фича. Не переходить к следующей фиче до принятия текущей.
- Перед реализацией: **краткий план** (модули, слои, новые компоненты, Decompose‑встраивание, use cases, интерфейсы/реализации, риски). Ждать апрув.
- После завершения: список изменений, спорные места, что проверить на ревью.
- После завершения: всегда **подробно и структурно** описывать реализованную логику и архитектуру функционала.
- В описании завершенной фичи обязательно раскрывать: какие компоненты добавлены/изменены, где хранится state, как проходит поток данных, как устроена навигация, как подключены use case / repository / platform abstraction.
- Коммит **только по прямому указанию**.
- не забывай про последние запятые

## Архитектура
- Чистая архитектура: domain / use cases / repository abstraction / data layer / presentation.
- Компонентный подход: каждая фича — изолированный компонент, минимальная связанность.
- Decompose: навигация через компоненты, state хранится в компоненте, UI тупой слой.
- Compose: stateless UI где возможно, state hoisting, preview‑friendly.
- Никакой бизнес‑логики в platform‑модулях без необходимости.
- Не менять архитектуру без согласования. Не рефакторить несвязанный код.
- Не добавлять сторонние библиотеки без согласования.
- Не нарушать границы модулей, не смешивать platform/shared без причины.

## Компоненты
- Каждый компонент: **interface + DefaultImpl + PreviewImpl (создавать только если есть указание)**.
- Каждый класс в **отдельном файле**.
- Каждый компонент — отдельный package (мини‑модуль: ui/domain/data/map и т.д.).
- `uiState` и `vmState` модели в каждой фиче/подфиче всегда хранить в package `.model`.
- В каждом Default‑компоненте использовать `CoroutineFeature`.
- `vmState` (Serializable) — логическое состояние.
- `uiState` — данные для UI, собираются в Assembler из vmState.
- Assembler — отдельный класс, передается в компонент как параметр (дефолтный экземпляр в параметрах).
- `StateStore` использовать для vmState, сохранять через `stateKeeper`.

## Навигация и стеки
- Стейт при переключении вкладок сохраняется.
- Не допускать дублей в стеке.
- Повторное нажатие на активную вкладку — возврат к корню.

## UI
- Использовать **UiText** для строк/ресурсов (новые случаи — обязателен UiText).
- Получение строк из ресурсов — в UI.
- Текст никогда не хардкодить (резолв иконок/названий объектов на основе эвристик — единственное исключение).
- Использовать дизайн‑систему, новые виджеты — только если нет подходящего.
- TopBar принадлежит конкретному экрану, не общая.
- Помечать классы `@Stable` при необходимости для избежания рекомпозиций.
- Использовать для списков `ImmutableList`.

## Репозитории / Интеректоры
- Методы в интерфейсах и интеракторах документировать блоком с целью, поведением, возвращаемыми значениями.

## Platform Dependencies
- Не передавать platform-specific зависимости в `commonMain` через `PlatformContext` и аналогичные контейнеры.
- Если shared-коду нужен platform capability, platform-specific объект должен создаваться на краю приложения (entrypoint / app layer платформы) и передаваться в shared через interface / factory / abstraction.
- Platform-модули отвечают за создание зависимостей и вызов platform API, но не за бизнес-логику фич.
